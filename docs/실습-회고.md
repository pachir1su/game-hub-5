# 5조 GitHub 협업 실습 회고

이 문서는 GitHub에 남아 있는 작업 기록을 기준으로 정리한 초안입니다.
팀원 각자의 경험과 팀 토론 결과는 실제로 이야기한 뒤 보완해야 합니다.

## 1. 가장 당황했던 순간

각자 개발한 게임은 정상적으로 동작했지만, 여러 사람이 수정한 `main.py`를 병합하는 과정에서 충돌이 생겼습니다.
게임 파일을 잘 작성했다고 해서 프로젝트 전체가 바로 완성되는 것은 아니라는 점을 확인했습니다.

특히 숫자야구 PR #19는 다른 게임들이 먼저 `main`에 반영돼 있어서 공용 메뉴 코드를 합치는 과정이 필요했습니다.

## 2. 충돌이 생긴 이유와 해결 방법

행맨, 숫자야구, 가위바위보, 틱택토 담당자가 모두 같은 `main.py`의 import 부분과 `GAMES` 메뉴를 수정했습니다.
서로 다른 브랜치에서 같은 부분을 바꾸면 Git이 어떤 변경을 남길지 자동으로 결정하지 못할 수 있습니다.

숫자야구 작성자는 최신 `main`을 자신의 브랜치에 병합하고 네 게임의 메뉴 항목을 모두 남겼습니다.
허브에서 추가한 `ask_choice()` 호출도 유지했습니다.
충돌을 해결한 뒤 다시 검사하고 리뷰어에게 재승인을 받았습니다.

앞으로는 공용 파일을 변경하기 전에 팀원들에게 수정 구간을 공유하고, PR을 너무 오래 열어 두지 않는 편이 좋겠습니다.

## 3. 코드 리뷰에서 배운 점

리뷰어가 단순히 코드만 읽는 것으로 끝내지 않고 직접 실행해 확인했습니다.
가위바위보에서는 README의 게임 상태 누락을 발견했고, 행맨에서는 입력 처리와 테스트가 보완됐습니다.
숫자야구에서는 메뉴 연결과 README 상태를 확인하도록 수정 요청이 남았습니다.

리뷰에서 지적한 부분을 수정한 뒤 같은 PR에서 재검토받는 방식이 필요하다는 것을 확인했습니다.

## 4. 실무에서 제안하고 싶은 규칙

- 개발하기 전에 최신 `main`을 받아 작업을 시작합니다.
- 게임 구현과 테스트를 가능한 한 작은 커밋으로 나눕니다.
- 공용 파일을 수정할 때는 담당자끼리 먼저 공유합니다.
- 모든 PR은 다른 팀원이 직접 실행하고 리뷰한 뒤 병합합니다.
- 병합할 때 기능이 사라지지 않았는지 메뉴와 자동 테스트를 다시 확인합니다.
